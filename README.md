# 交火线 · CROSSFIRE ARENA

第一人称对枪射击，支持多人联机。纯前端 + Firebase，没有后端服务器要维护。

---

> **第一次用？直接看 [SETUP.md](SETUP.md)** —— 从解压到联机的完整分步指南，每步都有验收标准。
>
> **中国大陆玩家**：用「连接码」模式，零配置。Firebase 在大陆连不上（Google 域名被墙，换哪个区域节点都没用）。

## 先跑起来看看（不配 Firebase 也能玩）

**不能双击 `index.html`。** 项目用了 ES 模块，浏览器出于安全限制不允许从本地文件加载，会白屏。必须通过 http 服务访问。

最快的办法，在项目文件夹里开个终端：

```bash
python3 -m http.server 8080
```

然后浏览器打开 `http://localhost:8080`。

不配 Firebase 时是**离线模式**，可以和机器人对枪，所有玩法都能试。

| 武器 | 类型 | 特点 |
|---|---|---|
| 暴徒 VANDAL | 步枪 | 全距离一枪爆头，万金油 |
| 幻影 PHANTOM | 步枪 | 射速更快，但远距离掉伤 |
| 斗牛犬 BULLDOG | 步枪 | **三连发**，一次扣扳机打三发 |
| 幽灵 SPECTRE | 冲锋枪 | 近战灵活，远了没准头 |
| 审判者 JUDGE | 霰弹枪 | 7 弹丸，要中 6 颗才秒，15 米外打不死人 |
| 战地狙 OPERATOR | 狙击枪 | 身体一枪必杀，走位极不准 |
| 元帅 MARSHAL | 轻狙 | 身体不秒但能连开两枪，机动高 |
| **六管绞肉机 MINCER** | 重机枪 | **要预热 1 秒才出弹**，扛着它移速只有 45%，180 发，散布大得像泼水 |
| 制式 CLASSIC | 手枪 | 免费副武器 |
| 左轮 SHERIFF | 手枪 | 高伤慢射，三枪爆头内解决 |
| 双子 TWINS | 手枪 | **双持交替**，射速快但散 |
| **苦无 KUNAI** | 飞刀 | **有飞行时间和下坠**，无声，爆头直接送走 |

绞肉机和飞刀是两套完全不同的玩法：

**绞肉机**按住左键会先听到转轮空转，一秒后才开始出弹。扛着它跑不动（2.7 m/s，步枪是 6），但有 180 发可以一直泼。DPS 比步枪低，赢在弹量和压制。

**飞刀**不是瞬时命中，刀飞出去要时间，还会下坠。10 米下坠 12 厘米（几乎不用调整），30 米下坠 1 米（要瞄对方头顶上方）。有效射程约 33 米，再远就插地上了。打中头部直接秒杀。

## 配置 Firebase 联机

### 1. 建项目

去 [Firebase Console](https://console.firebase.google.com) 新建项目。

### 2. 开实时数据库

左侧 **构建 → Realtime Database → 创建数据库**。

位置选 **asia-southeast1（新加坡）**——对越南和中国延迟最低。注意是 Realtime Database，不是 Firestore，两者不一样，这个游戏要的是前者。

### 3. 开匿名登录

左侧 **构建 → Authentication → 开始使用 → Sign-in method → 匿名 → 启用**。

玩家不用注册账号，进来就是一个匿名身份。

### 4. 设置数据库规则

把 `database.rules.json` 的内容粘贴到 Realtime Database 的「规则」标签页里，发布。

这套规则保证：**只有登录用户能读写，而且每个人只能改自己的玩家数据**，不能改别人的。

### 5. 填配置

项目设置 ⚙ → 滚到底部「你的应用」→ 点 `</>` 添加网页应用 → 复制那段 `firebaseConfig`。

打开 `js/config.js`，把里面的占位值替换掉。

> 这些值是公开的，放进 GitHub 公开仓库**没有安全问题**。真正保护数据的是上一步的数据库规则。

### 6. 验证

重新打开游戏，菜单底部应该显示绿色的「已连接 · 房间 arena-01」。

开两个浏览器窗口（或者一个正常窗口 + 一个隐身窗口），用**同一个房间号**进入，就能看到对方了。

```bash
npm install -g firebase-tools
firebase login
firebase init hosting   # public 目录填 . （当前目录）
firebase deploy
```

`firebase.json` 已经配好了，直接 deploy 即可。

## 联机有两种方式

### 一、连接码（中国可用，零配置）

不需要任何服务器。你生成一段码微信发给朋友，他回一段码，连上。之后游戏数据直接在你俩之间传。

原理是 WebRTC 的点对点连接在中国是通的，被墙的只是「帮两人互相找到对方」那一步，所以把这步改成人工。

- 邀请码约 600~900 字符，微信一条消息发得完
- 生成只要 1~3 秒
- **4 个人只需 3 次复制粘贴**——新人只和房主交换一次，之后房主自动帮他和其他人牵线

缺点是每次开局要多两步操作。适合 2~4 人固定小队。

### 二、Firebase 房间（需翻墙环境）

填个房间号就自动匹配，体验更顺。但 Firebase 的域名在中国大陆全部不可达，**换新加坡、东京、香港哪个节点都没用**——被挡的是域名本身不是地理位置。

两种方式的游戏数据都走 WebRTC 点对点，延迟一样。区别只在"怎么找到对方"。

### 为什么数据不走服务器

| | 经服务器中转 | WebRTC 直连 |
|---|---|---|
| 路径 | 你 → 机房 → 对手 | 你 ↔ 对手 |
| 延迟 | 80~200ms | 等于你俩的 ping |
| 频率 | 10~20Hz | 60Hz |
| 所需缓冲 | 110ms | 20~40ms |

数据通道配置成**不排序、不重传**（等价于 UDP）。丢一个位置包无所谓，16 毫秒后下一个就到了；绝不能排队重传，那才是延迟的真正来源。

**菜单里的「网络缓冲」滑杆**可以调到 0——完全不做延迟处理，零额外延迟，代价是对方动作会有轻微抖动。建议 20~40ms。这个值只影响 P2P；退回中转模式时程序会自动抬到 110ms，因为 15Hz 下低于 90ms 画面必然抖。

实测：60Hz 发包到达率 100%，P2P 模式下每帧位移误差为 0。

**连不上 P2P**：公司网、校园网的严格 NAT 会挡住直连。一方开手机热点通常能解决。彻底解决要自建 TURN 中继（香港轻量服务器约 ¥24/月）。

### 必须知道的一件事

**命中判定在客户端。** 你开枪、你本机算有没有打中、然后通知对方扣血。

懂技术的人改改 JS 就能作弊——发假伤害、改血量、改移速。朋友之间玩没问题，想做公开对战就必须加权威服务器复核每一发子弹，那是另一个量级的工程，Firebase 做不了（它只是数据库，不能跑游戏逻辑）。

## 文件结构

```
index.html              入口 + HUD 骨架
css/style.css           全部样式
vendor/three.module.js  three.js r160（随项目自带，不依赖 CDN）
js/
  main.js          菜单、启动流程、连接码交互
  game.js        核心引擎：移动、碰撞、射击、渲染
  net.js         网络层：P2P 优先，Firebase 兜底 + 插值缓冲
  webrtc.js        WebRTC 点对点连接（Firebase 模式用）
  manual-signal.js 手动连接码（中国可用，零服务器）
  projectiles.js 投掷物物理（飞刀的抛物线）
  bots.js        机器人 AI
  weapons.js     12 把枪的数值、弹道、伤害计算
  map.js         地图数据（改这里就能改关卡）
  hud.js         准星、血条、小地图、记分板
  config.js      Firebase 配置（你要改的）
database.rules.json     数据库安全规则
firebase.json           Hosting 配置
```

**three.js 是随项目自带的**，没用 CDN。因为 jsdelivr 在国内和越南时快时慢，万一抽风整个游戏就白屏。代价是仓库多 1.3MB。

## 想改点什么

**改地图** —— `js/map.js` 里的 `MAP.walls` 数组。每项 `p` 是中心点，`s` 是尺寸，`c` 是颜色。碰撞盒和可见模型都是从这一份数据生成的，改完直接刷新就生效。

**改武器数值** —— `js/weapons.js`。`dmg` 是 `[身体, 头部, 腿部]`，`moveMul` 是移动时散布放大倍数，`spray` 是前几发的固定弹道。

**改手感** —— `js/game.js` 顶部的常量：`SPD_RUN`（跑速）、`JUMP_V`（跳跃初速）、`GRAVITY`、`FRICTION`。物理用的是固定步长（1/120 秒），所以改完在任何帧率下表现都一致。

**加武器** —— 在 `WEAPONS` 里加一项，再在 `LOADOUTS` 里引用。视角模型是用 `model` 字段的几个数字程序化生成的，不需要 3D 建模。

几个特殊字段：`burst: 3` 三连发，`spinUp: 1.05` 预热秒数，`moveSlow: 0.45` 移速倍率，`dual: true` 双持交替，`pellets: 7` 霰弹丸数，`projectile: {speed, gravity}` 走抛物线而非射线。

**调联机延迟** —— `js/net.js` 的 `INTERP_DEFAULT_RTC`（P2P 缓冲）和 `webrtc.js` 的 `SEND_HZ_RTC`（发包频率）。

## 已知限制

- 命中判定在客户端，不防作弊（见上文）
- 严格 NAT 下 P2P 可能连不上，会退回中转模式
- 全互联架构，建议 6 人以内
- 没有回合制、经济系统、技能，是纯死斗
- 没有声音
- 移动端没做虚拟摇杆，目前只支持键鼠
